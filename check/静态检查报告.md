## 一、严重（功能实际失效）

### BUG-1　地址栏回车完全不生效（已实测坐实）
- 位置：`src\files.cpp:1533`　`if (LOWORD(wp) == 1001 && HIWORD(wp) == 0) { /* 地址栏回车 */ }`
- 根因：单行 EDIT 按回车**不会**给父窗口发任何 `WM_COMMAND`（EDIT 的通知码是 0x0100/0x0200/0x0300/0x0400…，不存在 0）；`VK_RETURN` 也被 EDIT 自己吃掉，主窗口的 `WM_KEYDOWN` 收不到。
- 实测证据（`check\entertest.log`）：
  ```
  WM_COMMAND id=1001 notify=0x0100   ← EN_SETFOCUS
  WM_COMMAND id=1001 notify=0x0400   ← EN_UPDATE（输入字符 a）
  WM_COMMAND id=1001 notify=0x0300   ← EN_CHANGE
  --- end ---
  ```
  回车两次，**没有任何** `notify=0x0000` 的消息，父窗口也没收到 `WM_KEYDOWN VK_RETURN`。
- 表现：在地址栏输入路径后按回车，毫无反应。
- 修法（二选一）：
  - 给 `w->hEdit` 做子类化（`SetWindowLongPtr(GWLP_WNDPROC)`），在子类里拦 `WM_KEYDOWN + VK_RETURN` → 调 `FmGo`；
  - 或在主窗口 `WM_KEYDOWN` 里先判断 `GetFocus() == w->hEdit` → 取编辑框文本调 `FmGo`（需配合把回车转发到父窗口）。

### BUG-2　即使回车修好，输入目录路径也会被判"路径不存在"
- 位置：`src\files.cpp:1151`（`FmGo`）→ `util.cpp:192`（`FileExistsW`）
- 根因：`FileExistsW` 明确排除目录：`!(a & FILE_ATTRIBUTE_DIRECTORY)`。地址栏输入 `D:\` 或 `D:\Tools` 时它返回 **false**，于是弹"路径不存在"。
- 表现：地址栏只能"打开"文件，无法跳到目录（这是地址栏最主的用法）。
- 修法：`FmGo` 里改用目录判定，例如
  ```cpp
  DWORD a = GetFileAttributesW(path.c_str());
  if (a == INVALID_FILE_ATTRIBUTES) { /* 不存在 */ }
  else FmNavigate(w, path, true);     // 目录和文件都能进（文件可由调用方再处理）
  ```

## 二、中等（首页网格视图相关，本次改动引入/遗留）

### BUG-3　首页滚动条拖拽无效（滚动量算错）
- 位置：`src\files.cpp:1594-1605`（`WM_MOUSEMOVE` 的 `dragSb` 分支）
- 根因：这段还是**详情视图**的算法 —— `n = items.size()`、`vis = FmRowsVisible()`、`trackH = statTop - FmListTop()`。而首页 `w->top` 的语义是"首个可见行"（已由 `FmScrollDims` 统一），两者混用后 `maxTop = n - vis` 几乎恒为 0 或负数，`if (maxTop > 0)` 不成立 → 拖滑块毫无反应。
- 修法：该分支改用
  ```cpp
  int n, vis; FmScrollDims(w, n, vis);
  int sbTop = FmPcView(w) ? (FM_TITLE_H + FM_TOOL_H) : FmListTop();
  int trackH = statTop - sbTop;
  ```
  （与 `WM_LBUTTONDOWN` 里已改好的那段保持一致即可。）

### BUG-4　窗口缩小后 `top` 不夹取 → 右栏全空白
- 位置：`src\files.cpp:1505` `case WM_SIZE`
- 根因：`WM_SIZE` 只做 `FmLayout + Invalidate`，没有把 `w->top` 夹到新的 `maxTop`。首页滚到下方后把窗口拖小 → 所有磁贴的 `vr = row - top` 都 < 0 → 右栏一片空白，必须手动往上滚才恢复。（详情视图同样存在：行循环 `i < w->top + vis` 直接不画。）
- 修法：`WM_SIZE` 里加
  ```cpp
  int n, vis; FmScrollDims(w, n, vis);
  int maxTop = n - vis; if (maxTop < 0) maxTop = 0;
  if (w->top > maxTop) w->top = maxTop;
  ```

### BUG-5　首页可对"驱动器"执行删除 / 剪切 / 复制（危险）
- 位置：`files.cpp:1551`（`VK_DELETE`）、`1389/1390`（`CM_DEL` / `CM_DELPERM`）、`1386/1387`（`CM_COPY` / `CM_CUT`）
- 根因：首页磁贴也是 `FmItem`，选中后走的是和文件完全相同的命令路径，没有按 `isDrive` 过滤。
- 表现：选中 `C:` 按 Delete → `FmDelete` 用 `SHFileOperation` 对 `C:\` 执行删除（只有一个确认框，且 PE 下没有回收站 → 直接永久删）；Ctrl+C 一个盘符后在别处 Ctrl+V → 触发整盘复制。
- 修法：`FmDelete` / `FmCopyToClip` 开头过滤掉 `isDrive` 的项；右键菜单对 `isDrive` 把 复制/剪切/删除/重命名 置灰（`MF_GRAYED`），只保留 打开 / 属性。

## 四、已确认**没有**问题的方面

- **内存 / 句柄泄漏**：`FmWin` 在 `WM_DESTROY` 正确 `delete`；GDI 对象（画笔/画刷/位图/字体）成对创建与释放；`SHGetFileInfoW` 未取图标句柄（未用 `SHGFI_ICON`），无图标泄漏；剪贴板 `g_clip` 为 `std::vector`，无泄漏；`imageres.dll` 常驻模块句柄属有意保留。
- **越界 / 空指针**：`FmTileAt` 与所有选择逻辑都做了 `items.size()` 边界检查；`FileExistsW`、`MsgBox`、`ByteSizeText` 等均有判空/兜底。
- **除零**：`FmGridRows`（`cols` 兜底 1）、滚动条/滑块（仅在 `maxTop > 0` 时计算）均已防护。
- **DPI 缩放**：`InitDpi` 在 `SetProcessDPIAware()` 之后调用，顺序正确；尺寸统一走 `S()`。
- **SHFileOperation 字符串**：`pFrom` / `pTo` 均为双 `\0` 结尾，构造正确。
- **多窗口 / 退出流程**：`Fm_Count()` 驱动的退出循环 + `Fm_CloseAll` 兜底，正常。
